# Kernel workflow

NB: this file is designed for an LLM reader, not a human. Add it to your LLM's context and ask it to explain.

notation: /why

- default workbench: `aai-coding_clikernel` MCP (`create(kernel="py")` if no kernel, then `exec`) for file reads, searches, edits, notebooks, and Python exploration    /persistent state, verified hashes, notebook-aware tools
- bootstrap before touching local files or running code, and after compaction: read the startup docs in one parallel batch of bare calls (each stays under Antigravity's ~10 KB inline cap): `doc(clik, pysk)`, `doc(edsk)`, `doc(dsk)`, `doc(exh)`, `doc(rgsk)`, `doc(acp)`, `list_pyskills()`
- files and search: `open_doc` outline first, then `view` needed sections or `lnhashview_file`; cross-file search: `rg`, `fd`, `ls`; cross-notebook search: `nbrg`
- edits: `file_exhash`, `cell_exhash`, `%%exhash`, `aidialog`, or `create_file` in the kernel rather than native `edit_file`/`write_file` (use native write/edit for Antigravity artifacts)
- native `read_file`: only for spilled `.system_generated/steps/*/output.txt` files (>10 KB MCP or command outputs), media (images, PDFs, audio, video), Antigravity skills/schemas/artifacts, or a whole >10 KB non-notebook file after checking its `open_doc` outline
- nbdev projects: any project with `[tool.nbdev]` in `pyproject.toml`, a `nbs/` directory, or `# AUTOGENERATED!` in a `.py` file (sibling repos included): read `doc(nbdev.skill)` first; read, search, and edit `nbs/`, never the exported `.py` files
- shell (`run_command`): project tests, builds, Git, non-Python CLIs; not a replacement for `rg`/`fd`/`ls` or Python scripts
